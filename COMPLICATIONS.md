# Complication Log — HWVAL (SRS-HWVAL-F767)

Running list of complications encountered while implementing the SRS,
section by section. One commit/push per SRS section, newest entries last.

| ID | Section | Complication | Discovered | Status / resolution |
|---|---|---|---|---|
| CL-001 | — | Repository had no git remote; SRS.md itself was untracked. | baseline | Created private repo `sandeshghimire/hwval-f767` via `gh`, added as `origin`, baseline commit includes SRS.md + this log. |
| CL-002 | §4 | `stm32-dev:latest` docker image not prebuilt; STM32CubeF7 v1.17.4 exists only inside it (CON-002 forbids local SDK copies). Builds must run in the container. | baseline | `scripts/docker-dev.sh build` started in background before §4 work; ~1.1 GB clone from GitHub required. |
| CL-003 | §4 | Host `arm-none-eabi-gcc` is the same 13.2.rel1 as the image, but no local SDK → cannot compile-check outside docker; every build iteration pays container startup. | baseline | Mitigation: single long-lived helper (`scripts/build.sh`, see §4 commit) and batched file writes. |
| CL-004 | §8 | Most of §8 is Level L (harness Appendix A), Level E (external equipment) or operator (O). The bench has the board but not the harness/equipment, so all hardware test code must implement ENV-002/ENV-003 gating: detect harness/equipment at runtime, else SKIP (`NO_HARNESS`/`NO_OPERATOR`/`NOT_FITTED`). | baseline | Test framework and every test group carry level/operator/destructive flags and preconditions from day one. |
| CL-005 | App. A | SRS Appendix A leaves the harness pin pairs to the design (OPEN-001). Pin pairs cannot stay undefined without blocking GPIO-004 and all L-level tests. | baseline | Pin pairs fixed in `board/hwval_board_pins.h` during §8.13 (GPIO), then SRS Appendix A filled and OPEN-001 closed in the appendices pass. |
| CL-006 | §4 | GEN-002 (flash + boot without debugger) and similar hardware-in-the-loop checks need exclusive ST-LINK access; anything holding OpenOCD (gdbserver) blocks flashing. | baseline | Rule: always flash/reset through `scripts/docker-dev.sh flash|reset`, never leave gdbserver running between sections. || CL-008 | §4 | The session CWD is reached via the `/home/sandesh/work` symlink; `docker-dev.sh` mixes logical (`pwd`) and physical (`realpath`) path resolution, so `flash build/hwval.elf` fails with "outside the project directory". | CL-002 | Workaround: `cd "$(pwd -P)"` before each docker-dev call (or pass absolute paths). Not modifying the committed script during section work. |
| CL-009 | §4 | SRS GEN-004 assumed `PWR VOSRDY` polling works; on this board/HAL (CubeF7 v1.17.4, F767 rev Z) `CSR1.VOSRDY` never sets (measured: 0 for >1.5 s while scale 1 was already active, still 0 at 216 MHz with over-drive ready). ST's own F767ZI-Nucleo application examples do not wait for VOSRDY either. | CL-002 | `hwval_clock_init` follows the ST example flow (scale config, over-drive, wait ODRDY/ODSWRDY instead). Verified live: CFGR=PLL, 7 WS, ART+prefetch on, ODRDY+ODSWRDY set. |
| CL-010 | §4 | **ST-LINK VCP one-way: board→host direction dead.** Evidence: (a) MCU USART3 TX completes (ISR TC=1, TXFE=1) yet host reads 0 bytes at 115200 with DTR/RTS set; (b) host→MCU works — `XYZ` sent from the host arrives (ISR RXFNE=1). So the TX-direction solder bridge between USART3 TX (PD8) and VCP_RX is open on this board; the RX-direction bridge is closed. | CL-002 | Bench action: close the TX-direction bridge (UM1974 SB122/SB123 pair — confirm designator on the silkscreen). Until then bench validation uses gdb/OpenOCD inspection; firmware-side USART3 is proven functional, so CLI-001/§6 code is unaffected. |
| CL-011 | §5 | SRS says "FreeRTOS V10.2.1" but CubeF7 v1.17.4 ships **V10.2.0** as-shipped (CON-002 forbids modifying SDK files; swapping the middleware would violate "as shipped"). | §5 | Used V10.2.0 as shipped; `hwval_freertos_version()` reports the true version (`"V10.2.0"`); noted in `board/FreeRTOSConfig.h` (CL-011 comment). SRS version string to be corrected in the final SRS pass. |
| CL-012 | §5 | FRT-005 asks the malloc-failed hook to "print the requested size", but FreeRTOS's `vApplicationMallocFailedHook` signature carries no size argument (V10.2). | §5 | Hook prints free + minimum-ever-free heap instead; size would require wrapping `pvPortMalloc` (project-owned wrapper can be added with §7 settings if needed). |
| CL-013 | §5.3 | Tick-rate test initially measured 2x drift: my TIM2 prescaler used PCLK1 directly instead of PCLK1x2 for APB1 timers (RM0410 rule). | §5 | Corrected in `test_rtos.c`; measured tick rate = 1003 ticks per 1.000 s (±0.3 %), FRT-023 PASS. Context switch 708 cycles, IRQ latency 33 cycles (FRT-024). |
| CL-016 | §8.6 | SRS CLK-012 requires the "LSE Clock Security System" but RM0410 (F76x RCC_BDCR) has no LSECSSON bit — LSE CSS does not exist on the STM32F767. | §8.6 | CLK-012 test reports N/A NOT_PRESENT with the register-map evidence; SRS appendix/coverage to be corrected in the final SRS pass. |
| CL-017 | §8.11 | SRS INT-001 states "112 IRQs"; the F767 startup/CMSIS vector list has 110 external interrupts (16 system + 110). | §8.11 | Test iterates the actual 110; SRS text to be corrected in the final pass.
